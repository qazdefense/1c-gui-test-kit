# Runtime-проверка клиента 1С

Используй `scripts/client-test.ps1` на Windows с разблокированным интерактивным рабочим столом. Инструмент запускает либо подключается к одному клиенту, ждёт готовности, выполняет заранее проверенный JSON-сценарий через UI Automation с координатным fallback и сохраняет снимки, дерево доступности и перечень окон. Журнал регистрации, технологический журнал и дампы собираются только по явным флагам.

## Порядок

1. Перед тестом закрой или явно переиспользуй клиент именно целевой базы. Не завершай процессы по одному лишь имени `1cv8.exe`.
2. До запуска проверь сценарий через `-ValidateScenarioOnly`. Для нового запуска передай параметры базы, `-URL`, клиент и сценарий. Для диагностики уже открытого клиента используй `-AttachProcessId`.
3. Сначала закрой только известные стартовые окна действиями сценария. Не классифицируй любое окно `1С:Предприятие` как безопасное.
4. Проверяй наблюдаемый результат: нужную вкладку, отсутствие неожиданного диалога, оба состояния переключателя и содержимое/видимость зависимых элементов.
5. Ссылайся на `result.json` и снимки. Запуск процесса или зелёная статическая проверка сами по себе не являются runtime-успехом. При тайм-ауте используй `FinalStage`, `process.json`, `windows.json` и `diagnostic-window.png`, если окно успело появиться.

## Команда

```powershell
powershell.exe -NoProfile -File "${CLAUDE_SKILL_DIR}/scripts/client-test.ps1" `
  -InfoBasePath "C:\Bases\MyDB" -UserName Admin `
  -URL "e1cib/list/Catalog.Товары" -Client Thick `
  -ScenarioPath ".\client-scenario.json" -OutputDir ".\build\client-test"
```

Проверка без запуска 1С:

```powershell
powershell.exe -NoProfile -File "${CLAUDE_SKILL_DIR}/scripts/client-test.ps1" `
  -ScenarioPath ".\client-scenario.json" -ValidateScenarioOnly
```

Схема сценария и доступные действия описаны в [references/scenario.md](references/scenario.md). `timeoutSeconds` повторяет поиск элемента или проверку условия до тайм-аута. Координаты допустимы только как явно отмеченный fallback и задаются относительно проверяемого окна. Для расширенной диагностики отдельно включай `-IncludeEventLog`, `-IncludeTechLog` или `-IncludeDumps`; дампы отбираются только по PID в имени. Артефакты могут содержать прикладные данные с экрана и из журналов: перед публикацией просматривай их и не добавляй в Git автоматически. Пароль `/P` виден операционной системе в командной строке процесса, поэтому используй отдельную тестовую учётную запись.
