# Автотесты GUI 1С через веб-клиент (Playwright, web-test)

Разбор граблей, найденных при написании первого сквозного GUI-автотеста
веб-клиента 1С (создание документа с присоединенным файлом, HTML-редактор,
предпросмотр, проведение). Все пункты подтверждены живым прогоном, а не
взяты из документации.

Инструмент — навык `web-test` из набора [cc-1c-skills](https://github.com/Nikolay-Shirokov/cc-1c-skills):
Playwright управляет реальным браузером поверх веб-публикации базы,
высокоуровневый API (`navigateLink`, `clickElement`, `fillFields`,
`getFormState`, `readTable`) плюс доступ к «сырой» странице через `getPage()`.

## 1. Поля HTML-документа — это отдельные iframe без URL

Поле формы вида `HTMLDocumentField` (редактор на Quill, предпросмотр,
любой встроенный HTML) в веб-клиенте отрисовывается в **отдельном iframe**
с пустым `url` (`about:blank`). Селектор на самой странице его не видит:

```js
await page.locator('.ql-editor')          // 0 элементов — редактор не найден
```

Искать надо перебором фреймов по содержимому:

```js
const findFrame = async (page, probe) => {
  for (const f of page.frames()) {
    try { if (await probe(f)) return f; } catch (e) { /* фрейм мог пересоздаться */ }
  }
  return null;
};
const editorFrame = await findFrame(page, async f => (await f.locator('.ql-editor').count()) > 0);
```

Предпросмотр ищется тем же способом — по тексту заголовка внутри `body`
фрейма. `try/catch` обязателен: при обновлении предпросмотра фрейм
пересоздается, и обращение к старому объекту падает.

## 2. Присоединение файла: свой диалог 1С, а не диалог браузера

Команда с `НачатьПомещениеФайла` в веб-клиенте **не открывает нативный
диалог выбора файла сразу**. Порядок такой:

1. 1С показывает свой модальный диалог «Выбор файла» (зона drag&drop,
   ссылка «выберите с диска», кнопки «Выбрать с диска» / OK / «Отмена»);
2. нативный диалог браузера открывается только по кнопке «Выбрать с диска».

Поэтому `page.waitForEvent('filechooser')` на клике по команде формы
виснет до таймаута — события еще нет.

Надежный способ — не эмулировать нативный диалог (он недоступен
автоматизации), а положить файл прямо в скрытый `input[type=file]`,
который 1С держит в своем диалоге:

```js
await clickElement('Загрузить...');                  // появился диалог «Выбор файла»
const fileInput = page.locator('input[type=file]#fileSelectButton');
await fileInput.setInputFiles('D:/path/cover.png');  // работает и со скрытым input
await page.getByText('OK', { exact: true }).filter({ visible: true }).last().click();
```

`id="fileSelectButton"` — стабильный идентификатор input-а в диалоге
платформы (проверено на 8.3.27, веб-клиент).

## 3. Кнопка OK в диалоге платформы — латиницей

В модальном диалоге «Выбор файла» подпись кнопки — **латинское `OK`**
(U+004F U+004B), тогда как соседняя «Отмена» — кириллицей. Поиск по
кириллическому «ОК» (U+041E U+041A) не находит ничего и падает по
таймауту. Проверяется в консоли браузера кодами символов:

```js
[...el.textContent.trim()].map(c => c.codePointAt(0))   // [79, 75] = латиница
```

При любом «элемент не найден, хотя он на экране» первым делом стоит
проверить коды символов подписи.

## 4. Кнопки модального диалога не попадают в состояние формы

`getFormState()` во время открытого диалога возвращает `modal: true` и
правильный `title` («Выбор файла»), но в `buttons[]` остаются кнопки
**основной формы** — кнопок самого диалога там нет. Нажимать их нужно
через «сырой» Playwright (`getByText`), а не через `clickElement`.

## 5. Имя присоединенного файла показывается без расширения

Реквизит типа `СправочникСсылка.<Объект>ПрисоединенныеФайлы` в поле
формы показывает **наименование** файла, а расширение хранится отдельным
реквизитом. Проверка вида `/\.png$/` на значении поля всегда ложна:

```js
cover.value                       // "post-cover", а не "post-cover.png"
```

## 6. Ctrl+Delete в веб-клиенте не помечает на удаление

Горячая клавиша пометки на удаление в списке из браузера не срабатывает
(перехватывается браузером), строка остается непомеченной. Рабочий путь —
через меню «Ещё», как это делает человек:

```js
const more = await clickElement('Ещё');               // вернет submenu[]
const item = (more.submenu || []).find(i => /пометить на удаление/i.test(i));
await clickElement(item);
await clickElement('Да');                             // подтверждение
```

Признак пометки в прочитанной таблице — служебное поле `_deleted: true`
у строки (`readTable()`).

## 7. Автотест обязан убирать за собой

Тест пишет в живую базу: каждый прогон оставляет документ и присоединенный
файл. Без финальной пометки на удаление после десятка отладочных прогонов
список замусоривается (живой случай — 11 лишних документов). Пометка на
удаление обратима, физическое удаление выполняется отдельной регламентной
операцией, поэтому уборку в конце сценария делать безопасно.

## 8. `/DisableStartupDialogs` роняет клиент на базе без авторизации

Относится к толстому клиенту (`1c-client-test`), но грабля того же рода.
Ключ `/DisableStartupDialogs` подавляет стартовые диалоги, **включая диалог
выбора пользователя**. На базе, где пользователи не заведены (вход без
авторизации), клиент с этим ключом молча завершается с кодом 1 ещё до
появления окна:

```
1C client exited before readiness (code 1)
```

Без ключа та же база стартует нормально. Вывод: ключ добавлять только
когда логин передаётся явно (`/N`), то есть когда в профиле базы есть
пользователь. Проверено на 8.3.27, файловая база.

Рядом второй момент того же класса: первый старт толстого клиента на
большой конфигурации занимает **150–190 секунд** (замер на «Бухгалтерии
для Казахстана 3.0»), и почти всё это время окно называется «Загрузка
конфигурационной информации...». Таймауты готовности в 60–240 секунд
срабатывают ложно — запас нужен кратный.

## 9. Публикация должна знать пользователя

Навык не умеет вводить логин/пароль в форму входа 1С: движок явно
сообщает «The engine cannot supply credentials». Пользователь должен быть
прописан в строке соединения публикации (`Usr=`/`Pwd=` в `default.vrd`),
иначе сценарий останавливается на диалоге авторизации.
