# Рецепты web-test: типовые приемы автоматизации веб-клиента 1С

Практический справочник «как сделать вот это» для сценариев GUI-тестов на
навыке `web-test` (Playwright поверх веб-клиента 1С). Дополняет разбор
граблей платформы: [Автотесты GUI 1С через веб-клиент — грабли платформы](gotchas.md).

Помечено, что проверено живым прогоном, а что взято из документации навыка
и ждет проверки.

## Коротко: хелперы вместо ручного кода

Большая часть приемов ниже уже упакована в хелперы, в двух вариантах с
одинаковыми именами:

- [`tests/_lib/1c-helpers.mjs`](../tests/_lib/1c-helpers.mjs) — для тестов
  `*.test.mjs`: `import { ... } from '../../_lib/1c-helpers.mjs'`, первым
  аргументом — `ctx` теста (`uploadFile(ctx, 'Загрузить...', путь)`);
- [`tests/_lib/1c-helpers.js`](../tests/_lib/1c-helpers.js) — для разовых
  сценариев `-Web -ScriptPath`: `gui-test.ps1` подставляет его перед
  сценарием, импорт и `ctx` не нужны (`uploadFile('Загрузить...', путь)`).

Ручной код в разделах ниже оставлен, чтобы было понятно, что происходит
внутри и как адаптировать прием, если хелпер не подошел.

| Хелпер | Что делает |
|---|---|
| `norm(s)` | убирает неразрывные пробелы (U+00A0) — для любых сравнений со значениями из 1С |
| `stamp(prefix)` | уникальная метка на прогон для тестовых данных (только `.mjs`) |
| `fail(msg)` | прерывает сценарий с понятным сообщением (только `.js`; в тестах — `assert`) |
| `fixture(name)` | абсолютный путь к файлу из `tests/_fixtures` |
| `getField(name)` | значение поля текущей формы |
| `findFrame(probe)`, `findFrameWithSelector(sel)`, `findFrameWithText(text)` | поиск поля HTML-документа (отдельный iframe) |
| `uploadFile(command, path)` | присоединить файл через диалог 1С «Выбор файла» |
| `clickDialogButton(caption)` | кнопка модального диалога платформы (их нет в `getFormState().buttons`) |
| `assertImageRendered(frame)` | картинка реально отрисована (`naturalWidth > 0`), а не просто есть тег |
| `findListRow(value, field)` | найти строку динамического списка через отбор (без отбора видно ~20 строк) |
| `markForDeletion(value, field)` | пометить строку на удаление через «Ещё» и проверить `_deleted` |

Примеры целиком на хелперах: тест —
[`examples/web-test/01-пост-с-картинкой.test.mjs`](../examples/web-test/01-пост-с-картинкой.test.mjs),
разовый сценарий — [`examples/run/post-with-image.js`](../examples/run/post-with-image.js).

## Почему веб-тест, а не скриншоты толстого клиента

Оба инструмента живут рядом (`1c-client-test` — толстый/тонкий клиент через
Windows UI Automation, `web-test` — браузер), но управляемость у них разная:

| | Веб-клиент (`web-test`) | Толстый клиент (`1c-client-test`) |
|---|---|---|
| Что видит тест | DOM страницы: поля с именами и значениями, строки таблиц, кнопки | дерево UI Automation, часто безымянные элементы |
| Проверки | значение поля, содержимое таблицы/отчета, текст и картинки в HTML-поле | наличие элемента, состояние переключателя, снимок окна |
| Ввод текста | целевое заполнение по имени реквизита | клавиатурный ввод в сфокусированный элемент |
| Запасной вариант | «сырой» Playwright: любой селектор, любое событие | клик по координатам относительно окна |
| Требования | база опубликована, пользователь в строке соединения | интерактивный разблокированный рабочий стол |

Отсюда правило: **если база опубликована — тестируем вебом**, толстый
клиент оставляем для того, что в вебе не воспроизводится (сам запуск
клиента, диалоги платформы уровня ОС, проверка версии клиента).

## Разведка перед сценарием (обязательный шаг)

Имена в 1С почти никогда не совпадают с ожидаемыми («Загрузить...», а не
«Загрузить»; «Ещё» с буквой ё). Сначала смотрим, что реально на форме:

```js
const form = await getFormState();
console.log(form.title, form.modal, form.formCount);
console.log(JSON.stringify(form.fields.map(f => ({ n: f.name, v: f.value, req: f.required }))));
console.log(JSON.stringify(form.buttons.map(b => ({ n: b.name, dis: b.disabled }))));
console.log(JSON.stringify(form.tabs));
writeFileSync('recon.png', await screenshot());
```

`getFormState()` — главный инструмент: он же показывает `modal: true`,
когда открыт модальный диалог, и `formCount` — сколько форм наложено.

## Открыть объект напрямую, минуя разделы

Быстрее и устойчивее, чем ходить по подсистемам (проверено):

```js
await navigateLink('Документ.УведомлениеСотрудников');   // список документов
await navigateLink('Справочник.Контрагенты');
await navigateLink('РегистрНакопления.ЗаказыКлиентов');
```

Навигация по разделам (`navigateSection('Продажи')`) нужна тогда, когда
проверяется именно командный интерфейс. Требует режима отображения панели
«Картинка и текст» либо «Текст» — по одним иконкам имена разделов
недоступны.

## Заполнение реквизитов шапки

```js
await fillFields({
  'Заголовок': 'Тестовый пост',
  'Организация': 'Ромашка',        // ссылочный реквизит — по представлению
  'ДатаНачала': '01.10.2026',
});
```

Текст вставляется через буфер обмена (так корректно отрабатывают события
формы 1С); буфер пользователя навык сохраняет и восстанавливает сам.

## Как добавить картинку (присоединенный файл)

Самый частый вопрос и самое неочевидное место. Команда формы с
`НачатьПомещениеФайла` открывает **свой диалог 1С**, а не диалог браузера,
поэтому ловить `filechooser` бесполезно — кладем файл в скрытый `input`
этого диалога (проверено живым прогоном):

```js
await clickElement('Загрузить...');          // 1С сначала запишет документ, потом откроет диалог
await wait(2);

const dlg = await getFormState();
if (!/Выбор файла/i.test(dlg.title)) throw new Error('Диалог не открылся: ' + dlg.title);

const page = await getPage();
await page.locator('input[type=file]#fileSelectButton').setInputFiles('D:/путь/cover.png');
await wait(3);

// ВНИМАНИЕ: подпись кнопки — латинское "OK", кириллическое "ОК" не найдется
await page.getByText('OK', { exact: true }).filter({ visible: true }).last().click();
await wait(5);

const cover = (await getFormState()).fields.find(f => f.name === 'Обложка');
if (!cover?.value) throw new Error('Файл не присоединился');
// в поле — наименование БЕЗ расширения: "cover", а не "cover.png"
```

Проверять результат лучше не по полю, а по тому, что картинка реально
отрисовалась там, где должна (например, в предпросмотре):

```js
const img = previewFrame.locator('img').first();
const { w, h } = await img.evaluate(el => ({ w: el.naturalWidth, h: el.naturalHeight }));
if (!w || !h) throw new Error('Картинка не загрузилась (naturalWidth=0)');
```

`naturalWidth = 0` — типичная ситуация «тег есть, файл не отдался»: без этой
проверки тест зеленый, а картинки нет.

## Работа с HTML-полями (редакторы, предпросмотр)

Поля `HTMLDocumentField` — отдельные iframe без URL, селектором со страницы
не находятся. Ищем перебором фреймов (проверено):

```js
const findFrame = async (page, probe) => {
  for (const f of page.frames()) {
    try { if (await probe(f)) return f; } catch (e) { /* фрейм мог пересоздаться */ }
  }
  return null;
};

// редактор (Quill)
const ed = await findFrame(page, async f => (await f.locator('.ql-editor').count()) > 0);
await ed.locator('.ql-editor').first().click();
await ed.locator('.ql-editor').first().type('Текст поста', { delay: 10 });

// предпросмотр — по характерному содержимому
const preview = await findFrame(page, async f => (await f.locator('body').innerText()).includes(TITLE));
```

## Табличные части

```js
await clickElement('Добавить', { table: 'Товары' });   // кнопка командной панели нужной ТЧ
await fillFields({ 'Номенклатура': 'Вентилятор', 'Количество': '5' });
const t = await readTable();                            // { columns, rows }
```

У строк есть служебные признаки: `_selected`, `_deleted`, `_predefined` —
по ним удобно проверять выделение и пометку удаления.

## Списки: поиск, выделение, открытие

```js
await filterList('Вентилятор');                              // отбор по всем колонкам
await filterList('Вентилятор', { field: 'Наименование' });   // по конкретной колонке
await filterList('Вентилятор', { field: 'Наименование', exact: true });
await unfilterList();                                        // снять отбор
await clickElement('Вентилятор');                            // одиночный клик — выделить строку
await clickElement('Вентилятор', { dblclick: true });        // двойной — открыть элемент
await clickElement('Строка 2', { modifier: 'ctrl' });        // добавить к выделению
```

### Проверять появление записи только через отбор

Динамический список отдает данные **порциями**: `readTable()` без отбора
вернет примерно первые 20 строк, а свежесозданный документ уходит в конец
списка по дате. Проверка «перебрать все строки и найти свою» дает ложное
падение — документ виден на экране, но в выборку не попал (живой случай,
`scroll: true` тоже не помог).

```js
// НЕ ТАК: вернутся только первые ~20 строк
const rows = (await readTable()).rows;
const found = rows.find(r => r['Заголовок'] === TITLE);   // ложное "не найдено"

// ТАК: сузили список — строка гарантированно в выборке
await filterList(TITLE, { field: 'Заголовок' });
const found = (await readTable()).rows.find(r => norm(r['Заголовок']).includes(TITLE));
await unfilterList();                                     // не оставлять отбор в списке
```

Отбор заодно ускоряет прогон и делает уборку за собой точной.

### Неразрывные пробелы в значениях ячеек

1С отдает в значениях **неразрывные пробелы** (U+00A0). На экране и в
логе строка выглядит обычной, но `===`/`includes` с обычным пробелом не
срабатывают. Высокоуровневый API навыка нормализует это внутри себя, а
собственные сравнения по `readTable()` — нет:

```js
const norm = (s) => String(s ?? '').replace(/\u00a0/g, ' ').trim();
if (norm(row['Заголовок']).includes(TITLE)) { /* ... */ }
```

«Не нашлось» — это ответ, а не повод перебирать варианты: если `readTable()`
**после отбора** пуст, элемента в базе нет.

## Пометка на удаление (уборка за собой)

Ctrl+Delete в браузере не работает — только через меню (проверено):

```js
await clickElement(TITLE);                  // выделить строку
const more = await clickElement('Ещё');     // вернет submenu[]
await clickElement((more.submenu || []).find(i => /пометить на удаление/i.test(i)));
await clickElement('Да');                   // подтверждение
```

Каждый сценарий, который создает данные, обязан их убирать: иначе после
десятка отладочных прогонов список забит мусором (живой случай — 11 лишних
документов в тестовой базе).

## Отчеты (СКД)

По документации навыка (живым прогоном пока не проверено):

```js
await clickElement('Остатки и доступность товаров', { dblclick: true });
await fillFields({ 'Склад': 'Основной склад' });   // отбор по человекочитаемому имени
await clickElement('Сформировать');
await wait(5);
const report = await readSpreadsheet();            // { columns, data, totals }
```

Отборы задаются по названиям, как их видит пользователь — знать
технические имена полей СКД не нужно.

## Модальные диалоги платформы

- `getFormState()` покажет `modal: true` и заголовок диалога, но **кнопки в
  `buttons[]` останутся от основной формы** — кнопки самого диалога туда не
  попадают. Жать их приходится «сырым» Playwright по тексту.
- Диалоги-вопросы (Да/Нет) отдаются в состоянии как `confirmation` — тогда
  достаточно `clickElement('Да')`.

## Когда нужен «сырой» Playwright

`getPage()` дает обычный объект `Page`: любой селектор, клавиатура, события,
оценка JS в контексте страницы. Это штатный запасной путь для всего, чего
нет в API навыка — загрузка файла в скрытый input, чтение `naturalWidth`
картинки, коды символов подписи кнопки:

```js
const codes = await el.evaluate(e => [...e.textContent.trim()].map(c => c.codePointAt(0)));
```

## Дисциплина сценария

1. Проверять **результат**, а не факт клика: открылась форма — это еще не
   тест.
2. Каждой проверке — внятное сообщение об ошибке с фактическим значением.
3. Не более двух попыток одного действия: не нашлось — сообщить, а не
   перебирать варианты по кругу.
4. Убирать за собой созданные данные.
5. Скриншоты писать относительным путем — рабочий каталог сценария и так
   папка артефактов прогона.
